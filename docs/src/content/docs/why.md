---
title: Why Astlide?
description: What Astlide is good at, how it compares to Slidev, Marp and reveal.js, and when to choose something else.
---

Astlide is for people who already like building with [Astro](https://astro.build) — or who want their slides to behave like the rest of their website.

## What makes it different

**It's an Astro integration.** Most slide tools are separate apps with their own build. Astlide is `astlide()` in your `astro.config.mjs`: talks live in the same repository as your blog or docs, reuse the same components and content collections, and deploy with the same pipeline.

**Every slide is a static page.** Each slide is its own URL and HTML file (`/my-talk/7`). You can link to a single slide, the page loads without a client-side app booting first, and any static host works — including sub-paths such as GitHub Pages.

**HTML is a first-class slide format.** Alongside `.mdx` and `.md`, a slide can be a plain `.html` file rendered verbatim (inline `<style>` included). That makes it easy to drop in hand-crafted layouts or HTML generated by an AI assistant without converting it.

**Many decks per project.** Every folder under `src/content/decks/` is a deck, and Astlide serves an index of them. Keeping a whole year of talks in one repository is the default, not a workaround.

**Type-safe content.** Frontmatter is validated with a Zod schema through Astro's content collections, and a typed API exposes deck and slide metadata to your components.

## How it compares

| | Astlide | Slidev | Marp | reveal.js |
|---|---|---|---|---|
| Built on | Astro (integration) | Vite + Vue (standalone app) | Markdown converter | JavaScript library |
| Slide formats | MDX, Markdown, HTML | Markdown + Vue components | Markdown | HTML / Markdown |
| Output | Static page per slide | Single-page app | HTML / PDF / PPTX | Single HTML page |
| Several decks in one project | Built in | One deck per entry | One file per deck | Manual |
| Presenter mode, pen, overview | ✓ | ✓ | Limited | ✓ (plugins) |
| Ecosystem & maturity | Young | Large, mature | Mature | Very mature |

*Comparisons are summaries — check each project's docs for current details.*

## When to choose something else

- **You want the biggest ecosystem of themes and add-ons** → [Slidev](https://sli.dev) is more mature and has far more community themes.
- **You want a single Markdown file and nothing else** → [Marp](https://marp.app) is simpler.
- **You don't use Astro and don't want a build step** → reveal.js or Marp will be lighter.
- **You need to edit slides visually** → a GUI tool (Keynote, PowerPoint, Google Slides) fits better. Astlide is code-first.

## Where Astlide is still young

Astlide is new. Its theme and plugin ecosystem is small, and some features other tools have are still on the [roadmap](https://github.com/r-hashi01/astlide/issues) — contributions are welcome.
